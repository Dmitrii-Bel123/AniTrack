# Правила работы AI-агента

## Git
- Перед началом проверь `git status` и текущую ветку.
- Не переключайся на другую ветку, если в рабочем дереве есть незакоммиченные изменения пользователя.
- Для каждой новой задачи создавай отдельную ветку от текущей базовой ветки. Формат: `ai/<short-task-name>`.
- Никогда не создавай коммиты и не выполняй `git commit`, `git push`, `git merge`, `git rebase` или `git reset` без моего явного разрешения.
- Не удаляй и не перезаписывай пользовательские изменения.
- Не используй `git stash`, чтобы автоматически скрывать изменения пользователя.

## Секреты и файлы
- Не открывай, не читай, не выводи в терминал и не передавай модели содержимое `.env`, `.env.*`, файлов с ключами, токенами, паролями, приватными сертификатами и другими секретами.
- Не меняй и не удаляй такие файлы.
- Можно читать `.env.example`, если в нём нет настоящих секретов.
- Если для задачи нужны секреты или доступ к защищённым файлам, остановись и спроси меня.

## Выполнение задач
- Сначала кратко изучи структуру проекта и предложи план.
- Вноси только изменения, необходимые для текущей задачи.
- Перед запуском потенциально опасных команд объясни, что они делают, и запроси разрешение.
- Не устанавливай новые зависимости, не меняй инфраструктуру и не запускай миграции без необходимости и моего согласия.
- После изменений запусти подходящие тесты и проверки, если это безопасно.
- Не утверждай, что тесты прошли, если ты их не запускал.
- В конце сообщи, какие файлы изменены, какие проверки выполнены и какие проблемы остались.

Если задача противоречит этим правилам, остановись и спроси меня.
